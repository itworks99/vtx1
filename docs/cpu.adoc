== CPU Microarchitecture

The core (`src/cpu/vtx1_core.v`) is a triple-issue, conversion-free
balanced-ternary machine: registers, PC, immediates, effective addresses
and all results are trit words end to end. The only trit-to-binary
conversion is `t2b()` toward the memory address bus (a chain of ×3
adds); there is no binary-to-trit conversion anywhere in the datapath.

=== Issue slots

The core instantiates three `vtx1_slot` units. Each slot decodes and
combinationally executes one operation word against the architectural
register file: its ALU result, effective address, branch decision,
control-flow target, plus the classification and hazard metadata
(destination and source register indices) the issue logic consumes. A
slot never writes state; the core commits only the slots it issues.

=== Dynamic issue rules

Up to three *consecutive* words commit per cycle. The hardware enforces
the VLIW packing rules itself:

* at most one memory operation per group;
* a control operation (branch/jump/RET/JR/JALR) or halt ends the group;
* DIV/MOD and PUSH/POP issue alone (multi-cycle, or two destinations);
* no intra-group RAW or WAW (TZ never conflicts): dependent words simply
  start the next group.

Co-issued words are therefore provably independent, and parallel commit
is bit-identical to sequential execution - which is why the ISA
simulator's retired-word count cross-check holds exactly.

=== Fetch

Instruction fetch has a fast path through the banked tightly-coupled
instruction memory (see the Memory chapter): during EXEC the next PC is
resolved combinationally - branch targets included - and the TCM read
for the next 3-word group is issued in the same cycle. TCM-resident code
therefore needs no fetch state at all: straight-line independent code
runs at up to 3 words per cycle, and taken branches cost zero extra
cycles. After a memory operation or divide, the already-fetched group is
still held in the TCM output registers, so the core resumes execution
with no refetch cycle. A TCM miss falls back to the bus port, one word
per fetch, single-issue.

=== Execution units

* *ALU* (`vtx1_alu.v`, one per slot): built from a balanced-ternary
  full-adder cell (`vtx1_trit_fa`) and an 18-trit ripple adder with
  tritwise negation on one input. ADD/SUB/MUL (an 18-partial product
  tree - Booth recoding is free in balanced ternary), AND = min,
  OR = max, XOR = product, NOT = NEG = tritwise negation, ABS, CMP and
  TEST, shifts and rotates, INC/DEC. Compare uses the overflow-correct
  rule: a nonzero carry-out trit of the subtraction is the true sign.
* *Iterative divider* (`vtx1_div.v`, shared): DIV/MOD in ~22 cycles.
  It operates on magnitudes (signs are applied for free by tritwise
  negation at the end), retiring one quotient digit per trit MSB-first
  with digits in {−2..2} on a 20-trit internal datapath; the natural
  result is the round-to-nearest quotient, converted to truncation by
  one correction step. Division by zero is trapped by the core before
  start.

=== State machine

FETCH, EXEC, LOAD, STORE, DIV and HALT. EXEC chains into EXEC on the TCM
fast path. LOAD/STORE hold a one-port word-addressed memory request with
a ready handshake, so the core connects equally to a simple synchronous
RAM or the SoC bus matrix; store data is latched at issue. The core
exposes `retired` (instruction words, cross-checked against the
simulator) and `cycles` (stops counting at halt).

=== The matched binary control

`src/control/rv32_triple/` is this exact microarchitecture with the trit
datapath replaced by two's-complement RV32IM: the same slots, issue
rules, FSM, TCM structure and memory model, by the same author. A cycle
difference between the two cores isolates the ISA; the Evaluation
chapter gives the results.
